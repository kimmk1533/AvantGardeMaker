	필드와 변수
==============================================================================================================================

 - 변수 이름에 명사 사용: 변수 이름은 사물이나 상태를 나타내므로 설명적이고, 명확하고, 모호하지 않아야 한다.
	따라서 bool 타입을 제외하곤 명사를 사용하여 명명해야 한다.
	
 - bool에는 접두사로 동사 사용: 이러한 변수는 true 또는 false를 나타낸다.
	종종 플레이어가 뛰는 중인가? 게임 오버인가? 등의 질문에 대한 답변이다.
	접두사로 동사를 붙이면 의미를 더 명확하게 알 수 있다.
	종종 이것은 설명 또는 상태와 함께 사용된다.
	(예시: isDead, isWalking, hasDamageMultiplier 등등)
	
 - 의미 있는 이름을 사용하며, 수학이 아니라면 축약하지 않는다: 변수명은 의도를 드러내야 한다.
	발음하기 쉽고, 검색하기 쉽고, 읽기 쉬운 이름을 선택해야 한다.
	(예를 들어, HorizontalAlignment가 AlignmentHorizontal보다 더 읽기 쉽다)
	
 - 반복문(for(int i = 0; )) 이나 수학 표현식에는 단일 문자를 사용해도 괜찮지만, 이외에는 축약하지 않는다.
	모음을 몇 개 생략하여 절약한 시간보다 더 중요한 것은 명확성이다.
	
 - 프로토타입을 만들 때 짧은 '임시' 이름을 사용하고 싶을 수도 있지만, 이렇게 하면 나중에 코드를 리팩토링 할 때 시간을 절약할 수 없다.
	시작부터 의미 있는 이름을 선택해라.

 - const 변수나 static 변수와 같은 특수 변수들은 접두사를 추가해라.
	일반 변수와 구분하는데 도움이 되며, 코드를 더 쉽게 읽고, 유지보수를 더 쉽게 만든다.
	일반적으로 const 변수에는 k_, static 변수에는 s_ 와 같은 접두사를 추가한다.
	(예시: public const int k_MaxItems = 100;, public static int s_LastIndex;)

 - 간결함보다는 가독성을 중요시해라.
	
피해야 할 예시:
 - int d;					(반복문이나 수학 표현식이 아니면 축약하지 않는다.)
 - string tName;			(반복문이나 수학 표현식이 아니면 축약하지 않는다.)
 - int mvmtSpd;				(반복문이나 수학 표현식이 아니면 축약하지 않는다.)
 - int getMovement-Speed	(변수명은 명사를 사용한다. 변수 타입이 bool이 아닌 경우, 동사는 메서드 또는 프로퍼티로 대신 사용한다.)
 - bool dead;				(bool은 true 또는 false로 대답할 수 있는 질문 형식이어야 한다.)
 
대체 예시:
 - private int elapsedTimeInDays;
 - private string teamName;
 - private int movementSpeed;
 - private bool isDead; or bool isPlayerDead;

------------------------------------------------------------------------------------------------------------------------------
==============================================================================================================================
	메서드
==============================================================================================================================

 - 동사 또는 Verb Phrases으로 이름을 시작해라.
	필요한 경우 context를 추가해라.
	(예시: GetDirection, FindTarget 등등)

 - 매개 변수에는 카멜 표기법을 사용해라.
	메서드에 전달된 매개 변수는 지역 변수와 똑같은 포맷을 사용한다.
	
 - bool값을 반환하는 메서드는 질문형으로 명명해야 한다.
	bool값 변수와 매우 유사하게, 질문의 형태로 true 또는 false 상태를 반환하는 동사를 접두사로 사용해라.
	(예시: IsGameOver, HasStartedTurn 등등)

==============================================================================================================================
	우리 게임 적용법
==============================================================================================================================

카멜 표기법(camelCase): 여러 단어를 연달아 사용할 때 각 단어의 첫 글자를 대문자로 적되, 맨 앞에 오는 글자는 소문자로 표기하는 것이다.
 - 모든 매개 변수
 - 모든 프로퍼티

파스칼 표기법(PascalCase): 연달아 오는 단어의 모든 앞글자를 대문자로 표기하는 것은 카멜 표기법과 같지만, 맨 앞에 오는 문자까지도 대문자로 표기한다.
 - private 멤버 변수 (접두사: m_)
 - protected 멤버 변수 (접두사: m_)
 - public 멤버 변수 (일반적으로 데이터 저장 자료구조에서만 사용, 그 외에는 사용 X)
 - 모든 멤버 함수
 - 매니저 사용 시 (접두사: M_)(접근지정자: private static 으로 고정)
 - 클래스 (MonoBehavior 스크립트인 경우, 클래스명과 파일명을 일치시켜야 함)
 - 구조체
 - 인터페이스 (접두사: I)
 - Enum (접두사: E_)
 
스네이크 표기법(snake_case): 단어 사이에 언더바_를 넣어서 표기하는 것이다.
 - 

기타
 - 인터페이스: 형용사 형식으로 명명
 
예시
 - private 멤버 변수: private int m_PrivateIntValue;
 - protected 멤버 변수: protected int m_ProtectedIntValue;
 - public 멤버 변수: public int PublicIntValue;
 - 프로퍼티: public int intValue { get; set; }
 - 매개 변수 & 멤버 함수: public int SetIntValue(int newIntValue) { }
 - 매니저: private static GameManager M_Game => GameManager.Instance;
 - 일반 클래스: public class Data { }
 - MonoBehavior 클래스: public class TestClass : SerializedMonoBehavior { }
 - 구조체: public struct TestStruct { }
 - 인터페이스: public interface IDeathable { public void Death(); }
 - Enum: public enum E_OperatorDirection { Up, Down, }
